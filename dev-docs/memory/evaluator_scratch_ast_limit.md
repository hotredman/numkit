# Evaluator ScratchArena AST Depth Limit

## Context
During the execution of the `contourf_filled.m` example, the script crashed with:
`Matrix dimensions must agree (in operator '.^')`
The crash happened precisely in the middle of a deeply nested mathematical expression (the classic MATLAB `peaks` function):
```matlab
Z = 3 * (1 - X).^2 .* exp(-X.^2 - (Y + 1).^2) ...
  - 10 * (X/5 - X.^3 - Y.^5) .* exp(-X.^2 - Y.^2) ...
  - exp(-(X + 1).^2 - Y.^2) / 3;
```
Here, `X` and `Y` were 60x60 matrices generated by `meshgrid`.

## Investigation & Bug Details
We isolated the sub-expressions and found that individual operators and precedence rules were parsed correctly. However, when the expression was evaluated as a single massive line, the `.^` operator deep inside the tree received corrupted matrix dimensions and threw the error, even though `X` was a valid 60x60 matrix and `2` was a valid scalar.

This occurs because `numkit` uses a `ScratchArena` (a fast memory resource arena allocator) to hold intermediate `Value` data during evaluation. When AST depth becomes too large for highly vectorized operations (like applying multiple binary operators to 60x60 matrices continuously in one statement), the `ScratchArena` either exhausts its temporary space or clobbers the shape headers of intermediate variables before the outer operations can consume them.

## Workaround
Until the core `ScratchArena` management or AST evaluator is hardened to spill or safely retain deeply nested temporaries, the workaround is to **break down complex vectorized expressions into intermediate variables**. 

In `contourf_filled.m`, pre-calculating the squared terms completely avoided the crash:
```matlab
% Pre-calculate squared terms to avoid AST depth/scratch memory limits
X2 = X.^2;
Y2 = Y.^2;
Z = 3 * (1 - X).^2 .* exp(-X2 - (Y + 1).^2) ...
  - 10 * (X/5 - X.*X2 - Y.*Y2) .* exp(-X2 - Y2) ...
  - exp(-(X + 1).^2 - Y2) / 3;
```
*(Note: Scripts like `surf_peaks.m` which compute the same function using scalar double `for`-loops are immune to this, because scalar evaluation does not allocate large scratch buffers).*
