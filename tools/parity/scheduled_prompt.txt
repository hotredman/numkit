A. Подготовка
   1. `git pull --rebase origin main` (избежать конфликта с ручными
      коммитами пользователя)
   2. `git status` — должно быть чисто. Если нет — НЕ продолжать,
      записать в diary "STUCK: dirty tree" и выйти без коммита.
   3. Прочитать BUGS.md и project_parity_cycle_progress.md полностью.

B. Выбор работы
   4. Из PARITY_PROGRESS.md выбери **до 30 функций со статусом ✅ и
      пустой ячейкой numkit_ms** (приоритет: верхние секции,
      Trigonometry / Arithmetic / Special Functions). Пропусти
      секции с namespace `categorical.*`, `table.*`, `datetime.*`,
      `ode.*`, `wavelet.*`, `linalg.*` — они требуют отсутствующих
      типов и помечаются SKIP.
   5. Для каждой — собери все сигнатуры через MATLAB
      `help <fn>` (через `matlab -batch`). Логи разбора в
      tools/parity/sigs/<fn>.json.

C. Auto-spec
   6. Для каждой сигнатуры — сгенерируй spec в
      tools/parity/specs_auto/<fn>__<sig_id>.json по эвристике:
        - unary numeric: setup x=linspace(...); expr y=fn(x);
        - binary numeric: x, y; z=fn(x,y);
        - reduction: s=fn(x);
        - constructor: A=fn(N, M);
        - predicate: p=fn(x);
      Auto-спеки которые точно не сработают (string-cell,
      multi-output destructure, side-effects типа figure/disp/error)
      — пометь "SKIP: needs manual spec" в comment ячейки PROGRESS,
      не запускай.

D. Прогон
   7. Запусти `python tools/parity/run_parity.py specs_auto/*.json`
      (или итеративно поспецово). Harness обновляет PROGRESS.md в
      месте; если функция в нескольких секциях — все вхождения.
   8. Любое расхождение (MISMATCH / THROW) — добавь запись в BUGS.md
      с severity (P0..P3), reproducer (минимальный), expected (MATLAB),
      actual (numkit), root cause (если знаешь — libs/ имя файла; если
      нет — "core, area unknown"), статус "pending — core fix required"
      или "pending — libs fix".

E. Валидация
   9. Полный test suite (с отфильтрованными известными flake'ами):
      ```
      build-desktop-fast/tests/Release/numkit_tests.exe \
        --gtest_filter="-TW_VM/MFileResolverTest.MultiOutputMFileResolves/*:\
        TW_VM/EvalRegressionTest.AssignmentCaptureSuppressesInnerAns/*:\
        TW_VM/EvalRegressionTest.BracketConcatInLoopInsideFunction/*" \
        --gtest_brief=1
      ```
      Должно быть 6378+ passed. Если меньше — в diary "STUCK:
      regression" и выйти.

F. Commit + push
   10. `git add -A && git commit -m "$(cat <<EOF
       parity bulk-bench: <N functions, M signatures>: A OK, B MISMATCH, C THROW, D MISSING, E SKIP

       <бельевая роспись по секциям и заметные расхождения>
       New BUGS.md entries: <id-list>
